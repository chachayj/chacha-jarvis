# 08. RC카 ESP32 개조 — Rastar 97400 Lamborghini Sián

> 정리일: 2026-09-07
> 대상: **RASTAR 97400** / 1:18 Lamborghini Sián FKP 37 / 조립식 RC 프라모델 키트
> 근거: 제품 동봉 매뉴얼(문서번호 `01.04.97400.00502`) 전문 + 제품 스펙 조사
> 상태: **설계 단계.** 키트 미개봉, 부품 미주문

순정 리모컨·수신기 대신 **파이에서 무선 명령을 보내고 차량 내부 컨트롤러가 모터를 제어**하는
구조로 바꾼다. 이미 구축된 `go_fiber_server -> EMQX -> 파이` 파이프라인 끝에 차량을 붙인다.

---

## 0. 역할 분리

```
[웹UI/챗봇]  →  [Raspberry Pi 4]  →  [ESP32]  →  [모터 드라이버]  →  [모터]
                  상위 제어기          차량 실시간 제어기   전력 공급        구동/조향
```

| 계층 | 담당 |
| --- | --- |
| Pi 4 | 명령 생성, MQTT 브로커, 상태 모니터링. **차량 외부** |
| ESP32 | WiFi 수신, PWM 생성, 워치독. **차량 내부** |
| 모터 드라이버 | 실제 전력 공급 (ESP32 는 신호만 만든다) |

### 왜 파이를 차에 넣지 않는가

차체가 **279 × 127 × 63mm / 500g** 이다. Pi 4 는 85×56mm 에 5V/3A 가 필요해서
보조배터리 무게를 4.5V·2.5mph 구동계가 끌지 못한다. **중량·전력 문제**다.

> 부수 결과: 보유 중인 **CSI 카메라(IMX219)는 차에 못 올린다.** CSI 는 파이 전용 리본이다.
> 영상을 하려면 ESP32-CAM 별도 또는 Pi Zero 2W 다.

> "Remote controller needs to match code with car **before each use**."

## 2. ⚠️ 조향은 비례 제어가 안 된다

이 문서에서 가장 중요한 제약이다. Step 17 주의문:

> "When installing the front gear box, please align the middle slot of the
> **fan shaped gear** to the middle pillar of the **connecting rod**."

**부채꼴 기어(sector gear)가 연결로드(타이로드)를 밀어 좌/우로 꺾는 구조**다. 서보가 아니다.

뒷받침 근거:

| 근거 | 내용 |
| --- | --- |
| 기능 목록 | `Turn Left` / `Turn Right` 뿐. 각도 표현이 없다 |
| 리모컨 | **화살표 버튼 4개** (비례 트리거·휠이 아님) |
| 조향 궤적도 | p.28 그림이 **고정 반경 원 하나** |
| `DIRECTION ADJUSTMENT` | 직진 트림 조정기가 별도로 있다 → 기계식 중앙복귀의 전형 |

### 설계에 미치는 영향

`{"steering": -20}` 같은 **연속 조향값은 순정 하드웨어에 매핑 대상이 없다.**
실제로 가능한 건 **좌 / 중앙 / 우 3상태**다.

**그럼에도 명령 스키마는 연속값(-1.0 ~ 1.0)으로 잡는다.** ESP32 가 임계값으로 뭉갠다.

- 나중에 서보로 교체할 때 상위 계층(웹UI·파이)을 안 고친다
- ROS 2 `geometry_msgs/Twist` 와 그대로 호환된다 (`angular.z`)

> 비례 조향이 필요하면 보유 중인 **SG90 서보**([04. 하드웨어 키트](04-hardware-kit.md) #03)로
> 교체 가능하다. 단 조향 링키지 기계 개조가 필요하고 **되돌릴 수 없다.**
> 1단계는 순정을 유지한다.

## 4. 커넥터 — 납땜이 필요 없다

Step 20:

> "Please press the wire into the gap.
> **Plug in respectively while matching by same colours and same shapes.**"

부품마다 **플러그의 색과 모양이 다르다.** 형상이 달라 오삽입이 물리적으로 불가능하다.

| 커넥터가 없다면 | 커넥터가 있으니까 |
| --- | --- |
| 전선을 자르고 납땜 | **플러그를 뽑으면 끝** |
| 실패하면 되돌릴 수 없음 | 다시 꽂으면 **순정 복구** |

### ⚠️ 규격이 달라 그냥은 안 꽂힌다

순정 플러그(JST 계열, 소형)와 ESP32 핀 헤더(2.54mm)는 규격이 다르다.

| 방법 | 판정 |
| --- | --- |
| **순정 플러그에 맞는 짝(하네스) 구매** | ✅ **권장** — 순정 100% 보존 |
| 점퍼선을 플러그 구멍에 꽂기 | ❌ 헐거워서 주행 중 빠진다 |
| 전선 자르기 | ⚠️ 최후수단. 되돌릴 수 없다 |

**규격(JST-XH / PH / ZH, 핀 간격)은 실물 사진으로만 특정된다.**
→ 하네스는 **조립 후에 주문**한다 (9장 5번 단계).

### 순정 PCB 를 파괴하지 않는다

`49` 를 커넥터에서 뽑는 것으로 끝내고 보드는 보관한다. 개조 실패 시 되꽂으면 순정으로 돌아간다.

## 5. 부품 선정

### 5-1. 모터 드라이버 — DRV8833 확정

4.5V 라는 값이 후보를 갈라버린다.

| | 입력 전압 범위 | 4.5V / NiMH 3.6V 에서 |
| --- | --- | --- |
| TB6612FNG | 브레이크아웃 하한 **4.5V** ~ 13.5V | 🔴 하한에 걸림. **NiMH(3.6V)에서 못 돈다** |
| **DRV8833** | **2.7V** ~ 10.8V | ✅ 알칼라인·NiMH 양쪽 커버 |

**제조사가 충전지(NiMH)를 공식 허용**하므로 3.6V 동작이 정상 범위다. → **DRV8833**.

- 채널당 연속 1.5A / 피크 2A → 1:18 구동계에 충분
- **듀얼 H-브리지라 주행 + 조향을 칩 하나로** 커버
- 과전류·과열 자동차단 내장 → 실측 없이도 파손 전에 스스로 멈춘다
- `nSLEEP` 핀을 GPIO 로 잡아 **하드 정지 경로**를 확보한다

> 감수할 것: 드라이버 자체 전압강하(RDS(on) 약 360mΩ → 1A 에서 ~0.36V)로
> **순정보다 느려진다.** 원래 2.5mph 인 차라 체감된다.

### 5-2. ESP32 보드 — C3 Super Mini

차체 높이가 **63mm** 이고 Sián 은 극단적으로 낮다.

| 보드 | 크기 | 판정 |
| --- | --- | --- |
| ESP32 DevKitC | 약 55×28mm + 핀헤더 두께 | 🔴 안 들어갈 위험 |
| **ESP32-C3 Super Mini** | 약 **23×18mm** | ✅ 권장. 핀헤더 없이 직접 납땜 |

C3 는 LEDC 채널이 6개(ESP32 는 16개)지만 필요한 건 **주행 2 + 조향 2 + 헤드라이트 1 = 5채널**이라 충분하다.

### 5-3. ⚠️ 모터 노이즈로 ESP32 가 리셋된다

가장 흔한 실패다. 브러시 아크 → 전원 리플 + EMI → 브라운아웃 리셋.

**노이즈 대책 2개는 무조건 한다:**

1. 모터 단자에 **0.1µF 세라믹 3개** (단자간 1개 + 각 단자→케이스 1개씩)
2. 드라이버 `VM` 에 **470~1000µF 전해** 벌크 캡

#### 전원을 나눌지는 단계적으로 판단한다

**리포를 처음부터 사지 않는다.** 아래 순서로 올라간다.

| 순서 | 방법 | 비용 | 판단 |
| --- | --- | --- | --- |
| 0 | **책상 테스트(9장 6~7번)** — ESP32 는 PC USB, 모터는 AA | 0원 | 애초에 문제가 안 생긴다 |
| 1 | **AA 팩 공용** — AA 4.5V 를 ESP32 `5V` 핀에 함께 물린다 | 0원 | ⭐ **먼저 이걸 시도한다** |
| 2 | ESP32 `5V`↔`GND` 에 **470µF 벌크 캡 추가** | 0원 (이미 있음) | 1번이 실패하면 |
| 3 | **1S 리포 별도** | ~1만원 | 2번도 실패하면 |

**왜 1번이 실패할 수 있는가 — 전압이 아니라 내부저항 때문이다.**

AA 3개면 4.5V 이고 C3 의 온보드 레귤레이터는 강하가 작아서 **전압 자체는 충분하다.**
문제는 **AA 알칼라인의 내부저항**(팩 전체 0.5~0.9Ω)이다.
모터 구동 + WiFi 송신이 겹쳐 순간 1.5A 가 흐르면 **전압이 1V 가까이 꺼지고**,
3.5V 이하로 내려가면 ESP32 가 리셋된다.

#### "리셋"이 뭔가

**ESP32 가 저절로 재부팅되는 것**이다. 서버 프로세스가 죽고 다시 뜨는 것과 같다.

```
"전진" 명령 도착
   → 모터가 돌기 시작, 배터리에서 전류를 확 뽑음
   → 배터리 전압이 순간 4.5V → 3.4V 로 꺾임
   → ESP32 가 "전압 부족" 을 감지해 스스로 재부팅 (브라운아웃 리셋)
   → 프로그램이 처음부터 시작, WiFi·MQTT 연결 끊김
   → 재접속에 2~3초 → 다시 명령 받음 → 또 모터 → 또 리셋 (무한 반복)
```

**눈에 보이는 증상**

- 차가 **찔끔 가다 멈추기를 반복**한다
- USB 로 PC 에 연결해두면 **시리얼 모니터에 부팅 메시지가 계속 다시 올라온다**

이게 보이면 **전원 문제**다. 코드를 고칠 일이 아니다.

**대응의 원리**

| 대응 | 원리 |
| --- | --- |
| 470µF 캡 추가 | **작은 물탱크**를 다는 것. 전류가 몰릴 때 캡이 먼저 내주니 전압이 안 꺾인다 |
| 리포 분리 | ESP32 에게 **전용 배터리**를 주는 것. 모터가 뭘 하든 영향받지 않는다 |

캡으로 해결되면 지출이 없다. 그래서 캡을 먼저 시도한다.

> ⚠️ **공용으로 갈 거면 반드시 알칼라인을 쓴다.** NiMH 는 3.6V 라 처음부터 여유가 없다.
> (모터만 구동할 때는 NiMH 도 정상이다 — 제조사 허용 범위)

## 6. ⭐ 배터리베이가 그대로 ESP32 하우징이다

매뉴얼에서 나온 가장 실용적인 발견이다.

- `54` 배터리박스는 **독립 모듈**로 `45` 에 얹힌다 (Step 21)
- 커버 `C28` 은 **차체 하부에서 동전으로 `C22` 를 돌려** 여닫는다 (Step 22)

```
54 배터리박스 (3×AA 자리)
  → 3×AA 제거
  → ESP32-C3 + DRV8833 + 1S 리포 수납
  → USB 포트를 C28 커버 개구부 쪽으로 배치
```

**차를 분해하지 않고 펌웨어를 플래싱할 수 있다.** 개발 중 이건 결정적인 차이다.
안 그러면 코드 수정마다 바디를 뜯어야 한다.

3×AA 를 빼면 **공간 문제와 전원 분리가 동시에 해결된다.**

## 7. 소프트웨어 설계

### 7-1. ⚠️ 브로커 위치 — 파이에 둔다

**현 토폴로지에서 ESP32 는 브로커에 붙을 방법이 아예 없다.**

[`embeded/rpi/README.md`](../../rpi/README.md) 에 실측 기록된 현재 상태:

- EMQX 는 **개발 PC 도커**에 있다
- 파이와 개발 PC 는 **서로 다른 회선**이다
- 파이는 **Tailscale IP(`100.78.253.44`)** 로 브로커에 붙는다

**ESP32 에는 Tailscale 클라이언트가 없다.**

포트포워딩으로 뚫어도 제어 경로가 `브라우저 → 개발PC EMQX(다른 회선) → ESP32` 가 되어
**인터넷이 끊기면 달리던 차가 그대로 돌진한다.** 실시간 제어를 WAN 왕복에 걸면 안 된다.

#### 해결: 파이에 로컬 브로커 + 원격 EMQX 와 브리지

```
[웹UI/챗봇] → [개발PC EMQX] ──bridge(Tailscale)──→ [파이 로컬 broker] → [ESP32]
                                                          ↑ 같은 WiFi, 1홉
```

- 제어 루프가 파이↔ESP32 **로컬 1홉**(수 ms) → 인터넷 끊겨도 조작 유지
- 챗봇/웹 경로는 브리지로 살아있어 **기존 토픽 계약을 그대로 재사용**
- mosquitto·EMQX 둘 다 bridge 가 내장 기능이라 코드 작업이 없다

**이게 우선순위 1번이다.** 여기가 안 정해지면 나머지 설계가 공중에 뜬다.

### 7-2. 토픽 계약

기존 계약(실측):

| | 값 | 근거 |
| --- | --- | --- |
| 발행 토픽 | `/Robot_Control_Command/{robotId}` | `mqtt_client.go:126` |
| 페이로드 | `{"command": "<자연어 문자열>"}` | `robot_manager.go:33` |
| QoS / retain | **0 / false** | `mqtt_client.go:128` |
| 상태 토픽 | `/Robot_Status/{robotId}` | `led_mqtt.py` |
| HTTP 진입 | `POST /robots/{id}/control` | go 서버 README |

기존 계약은 **자연어 문자열 1개**다(챗봇 "불 켜줘" → 키워드 매칭).
연속 주행 제어에는 맞지 않으므로 **채널을 분리한다.**

| 용도 | 토픽 | QoS | retain | 주기 |
| --- | --- | --- | --- | --- |
| 이산·자연어 명령 (챗봇) | `/Robot_Control_Command/{id}` *(기존 유지)* | 1 | false | 이벤트 |
| **연속 주행 제어** | `/Robot_Drive/{id}` *(신규)* | **0** | **false** | 10~20Hz |
| 텔레메트리 | `/Robot_Status/{id}` *(기존)* | 0 | false | 1~5Hz |

세 가지를 반드시 지킨다:

- **연속 제어는 QoS 0.** QoS 1 은 재전송 큐가 쌓여 **오래된 조향값이 나중에 도착한다** — 제어에서 최악이다
- **retain 은 절대 false.** retain 된 "전속 전진"이 재접속 때 재생돼 차가 튀어나간다
- **`robot_id` 를 LED(`1`)와 다르게 잡는다.** 같으면 `led_mqtt.py` 의 키워드 매칭이 차량 명령을 먹는다
  (`ON_WORDS` 에 `"start"`, `"켜"` 가 들어있다)

#### 페이로드 — ROS 2 Twist 호환

```json
{ "seq": 1042, "throttle": 0.6, "steer": -1.0, "ts": 1757203200123 }
```

| 필드 | 매핑 / 용도 |
| --- | --- |
| `throttle` | `linear.x` (-1.0 ~ 1.0) |
| `steer` | `angular.z` (-1.0 ~ 1.0) |
| `seq` | 순서 역전 폐기 — 이전보다 작으면 버린다 |
| `ts` | 워치독·지연 측정 |

레포가 ROS 2 Jazzy 를 목표로 하므로([`embeded/ros/`](../)), 나중에 micro-ROS 로 갈 때
스키마를 안 고친다.

### 7-3. ⚠️ 워치독 — 없으면 차가 벽에 박는다

WiFi 가 끊기면 ESP32 는 **마지막 PWM 을 계속 유지한다.**

```
명령 수신 시:  마지막_명령_시각 = now()

매 루프:      if (now() - 마지막_명령_시각 > 300ms) → 모터 정지
```

필수 4종:

1. 마지막 명령 후 **200~300ms** 내 새 명령 없으면 즉시 정지
2. MQTT 연결 끊김 감지 → 즉시 정지 (재연결은 정지 상태로 시도)
3. 부팅 직후 기본 상태 = 정지 (첫 명령 전엔 절대 안 움직임)
4. DRV8833 `nSLEEP` 을 GPIO 로 잡아 하드 정지 경로 확보

**MQTT 를 붙이기 전에 워치독을 먼저 만든다.** 순서를 뒤집으면 첫 연결 끊김에 차가 돌진한다.

### 7-4. ⚠️ 2.4GHz 대역 간섭

순정 무선은 **2400~2483.5MHz / ≤10mW** 로 **WiFi 와 같은 밴드**다.
순정 수신기를 차 안에 폴백으로 남겨두면 ESP32 WiFi(≈100mW)가 10mW 링크를 깎는다.

→ **폴백 보드·리모컨은 차에서 빼서 보관한다.**

### 7-5. 안테나 배치

Step 15 에서 제조사가 안테나 위치를 지정한다:

> "the `49` **antenna** should be placed in the **`+` position of the battery box** to ensure a good signal"

**ESP32 안테나도 같은 원칙**을 따른다 — 모터 배선·배터리 금속판에서 떼고, **절대 감아두지 않는다.**

## 8. ESP32-C3 핀 선택

> ⚠️ **C3 는 클래식 ESP32 와 핀 제약이 완전히 다르다.** 인터넷 예제 대부분은
> 클래식 ESP32(`GPIO 34~39 입력전용`, `6~11 플래시`) 기준이라 그대로 쓰면 안 된다.

### 쓰면 안 되는 핀 (ESP32-C3)

| 핀 | 이유 |
| --- | --- |
| `11 ~ 17` | 내장 플래시 SPI — 절대 금지 |
| `18`, `19` | USB D- / D+ — USB 로 플래싱하면 못 쓴다 |
| `20`, `21` | UART0 (시리얼 모니터) |
| `2`, `8`, `9` | **스트래핑 핀** — 드라이버 입력이 풀업/풀다운돼 있으면 **부팅이 안 된다** |

> C3 에는 **입력 전용 핀이 없다.** 위 목록만 피하면 나머지는 입출력 자유다.

### 권장 핀 배정

| 용도 | 핀 | 비고 |
| --- | --- | --- |
| DRV8833 `AIN1` (구동) | `GPIO 3` | PWM |
| DRV8833 `AIN2` (구동) | `GPIO 4` | PWM |
| DRV8833 `BIN1` (조향) | `GPIO 5` | 디지털로 충분 |
| DRV8833 `BIN2` (조향) | `GPIO 6` | 디지털로 충분 |
| DRV8833 `SLP` (하드 정지) | `GPIO 7` | 디지털. `LOW` = 전 채널 정지 |
| 헤드라이트 | `GPIO 10` | 디지털 (밝기 조절하려면 PWM) |
| **내장 LED** | `GPIO 8` | ⚠️ 스트래핑 핀이지만 **출력 전용으로 쓰는 건 무해**. 워치독 LED 테스트용 |

조향은 비례 제어가 안 되므로(2장) **PWM 이 아니라 디지털 HIGH/LOW 로 충분**하다.

### PWM 은 LEDC 로

`analogWrite` 가 아니다. C3 의 LEDC 는 **6채널 / 4타이머**다.

| 대상 | 주파수 | 채널 |
| --- | --- | --- |
| 구동 모터 | **20kHz** | 2 (가청 대역 위 → 모터가 낑낑거리지 않는다) |
| 헤드라이트 (선택) | 1kHz | 1 |
| (나중에) 서보 | 50Hz | **20kHz 와 다른 타이머**를 써야 한다 |

구동 2 + 헤드라이트 1 = 3채널이라 6채널 안에 충분히 들어간다.

## 9. 작업 순서

### A. 준비

**1. 부품 주문** — 5-4 표 참조. **하네스는 아직 주문하지 않는다.**

**2. 매뉴얼대로 순정 조립** — Step 1~22 전부, 개조 생각 없이. AA 3개 넣고 완성.

**3. ⚠️ 리모컨으로 주행 확인** — **필수 관문**
여기서 안 움직이면 조립 문제다. 통과 전엔 절대 다음으로 넘어가지 않는다.
순정으로 한 번 달려봐야, 이후 모든 실패 원인이 "내 배선"으로 좁혀진다.

**4. 사진 촬영 + 공간 실측**
- 커넥터 4개(구동/조향/헤드라이트/배터리) **색·모양·핀 개수**
- 배터리베이(`54`) 내부 치수 — ESP32+DRV8833+리포가 들어가는지
- `C28` 커버를 열었을 때 USB 포트에 손이 닿는 위치인지

**5. 커넥터 규격 확인 → 하네스 주문** — 4장 참조

### B. 하드웨어

**6. 책상에서 배선** — 차체 밖에서

```
1S 리포    → ESP32
AA 배터리  → DRV8833 → 모터 2개
ESP32     → DRV8833 (신호선)
```

콘덴서도 이때 같이 단다 (5-3).

**7. ⚠️ 하드코딩으로 모터 회전 확인** — **필수 관문**
"3초 전진 → 정지 → 3초 후진" 수준. WiFi 없이. **속도는 30~40% 로 제한.**
바퀴를 손으로 잡고 오래 누르지 않는다 (스톨 = 전류 최대).

### C. 소프트웨어

**8. 워치독 구현** — 7-3

**9. 파이에 로컬 브로커 기동 + 개발PC EMQX 브리지** — 7-1

**10. ESP32 를 브로커에 연결** — `/Robot_Drive/{id}` 신규 토픽, 7-2

**11. ⚠️ 안전 테스트** — **필수 관문**
**브로커를 끄고 차가 즉시 멈추는지 확인.**
안 멈추면 워치독이 잘못된 것이다. 이 상태로 12번에 가지 않는다.

### D. 마무리

**12. 차체 탑재** — 배터리베이에 수납, USB 를 커버 쪽으로 (6장)

**13. 실주행**

**14. 헤드라이트 연결** — ESP32 GPIO 1개 + 220Ω
→ 이미 만들어둔 챗봇 "불 켜줘" 경로가 그대로 차량 헤드라이트로 재사용된다.
[`embeded/rpi/README.md`](../../rpi/README.md) 의 미완 항목 해소.

**15. 텔레메트리** (선택) — `/Robot_Status` → Cesium 3D 지도 표시

## 14. 부록 — 실작업 상세

### 14-1. 커넥터 사진 — 무엇을 왜 어떻게 찍나

**왜 찍나**
ESP32 를 연결하려면 순정 플러그와 **짝이 되는 커넥터**를 사야 한다.
그 규격은 **핀 간격(피치)** 으로 결정되고, 피치는 눈으로 봐선 구분이 안 된다.
사진에 자를 같이 담아두면 나중에 규격을 특정할 수 있다.

**어디에 있나**
하부 섀시(`45`)에 보드 `49` 가 얹혀 있고, **모터·헤드라이트·배터리·스위치 배선이 전부 `49` 로 모인다.**
매뉴얼 Step 20(p.24) 그림이 그 배선 전체도다.

**무엇을 찍나** — 플러그 4개(구동모터 / 조향모터 / 헤드라이트 / 배터리) 각각:

1. 플러그를 뽑아서 **정면** (구멍 또는 핀이 보이게)
2. **옆면** (하우징 모양)
3. ⭐ **자 눈금 옆에 대고** 찍은 것 — 이게 제일 중요하다

**핀 간격(피치) 구하는 법**

| 핀 수 | 계산 |
| --- | --- |
| 2핀 | 두 핀 **중심** 사이 거리 = 피치 |
| 3핀 이상 | (첫 핀 중심 ~ 마지막 핀 중심) **÷ (핀 수 − 1)** |

> 2핀 하나만 재면 오차가 크다. 핀이 여러 개인 헤드라이트 커넥터로 재면 정확도가 올라간다.

**피치 → 규격 대조표**

| 피치 | 규격 | 비고 |
| --- | --- | --- |
| 1.0mm | JST SH | 드물다 |
| 1.25mm | JST GH / Molex PicoBlade | |
| 1.5mm | JST ZH | |
| **2.0mm** | **JST PH** | ⭐ 장난감에서 가장 흔하다 |
| 2.5mm | JST XH | |
| **2.54mm** | **범용 핀헤더 (듀폰)** | ⭐ 이러면 **흔한 점퍼선이 그냥 맞는다** |

2.0mm 와 2.54mm 는 차이가 0.5mm 라 눈으로는 구분이 안 된다. **반드시 실측한다.**

### 14-2. 미확정 5개 — 확인 절차

| # | 확인 대상 | 구체적으로 무엇을 하나 | 결과에 따라 |
| --- | --- | --- | --- |
| 1 | 커넥터 규격 | 14-1 절차대로 피치 실측 | 2.54mm → 점퍼선으로 끝 / 그 외 → 하네스 주문 |
| 2 | `47+48` vs `50` 배치 | Step 17 조립할 때 **어느 부품을 앞에 넣었는지 메모.** 완성 후엔 뒷바퀴를 손으로 굴려서 **모터가 같이 도는 쪽이 구동** | 드라이버 채널 배정 (구동=A, 조향=B) |
| 3 | `DIRECTION ADJUSTMENT` | 차 밑 조정기를 좌우로 끝까지 돌리면서 **앞바퀴를 본다** | **앞바퀴가 물리적으로 틀어지면 기계식** → 그대로 유지<br>**변화 없고 전선이 `49` 로 가면 전기식** → 보드 떼면 무효, 트림을 ESP32 소프트웨어로 이관 |
| 4 | `51` 헤드라이트 도체 수 | 리본 케이블의 **전선 개수를 센다** | 2개 → 전조등만, GPIO 1개<br>4개 이상 → 후미등 포함 가능, GPIO 2개 |
| 5 | `54` 배터리베이 | `C22` 를 동전으로 돌려 `C28` 커버를 열고 **가로 × 세로 × 깊이** 를 자로 잰다. 그리고 **커버 구멍에서 USB 케이블이 들어갈 방향**을 확인 | ESP32 수납 가능 여부 / USB 포트 방향 결정 (6장) |

> 2번은 **조립 중에만 쉽게 확인된다.** 다 조립한 뒤엔 안 보인다. Step 17 할 때 사진을 찍어둘 것.

### 14-3. 하네스 주문 — 결정 트리

```
14-1 에서 잰 피치가 2.54mm 인가?
  │
  ├─ YES → 아무것도 안 사도 된다.
  │        흔한 점퍼선(듀폰 케이블)이 그냥 꽂힌다.
  │
  └─ NO  → 하네스가 필요하다
             │
             ├─ 규격이 특정됨 (예: PH 2.0mm 2핀)
             │    → "JST PH 2.0 2핀 커넥터 케이블" 주문
             │
             └─ 애매하다 / 자신 없다
                  → ⭐ JST 종합세트 (PH·XH·ZH 혼합, 암수 포함) 주문
                     만원 안팎이고, 이게 가장 안전하다
```

**암/수 헷갈리는 문제**

| 위치 | 보통 |
| --- | --- |
| 모터 전선 끝 | **암** (플라스틱 하우징에 구멍) |
| 보드 `49` 위 | **수** (핀이 튀어나옴) |

`49` 를 떼면 **암 플러그들이 남으므로, 내가 사야 할 건 수 핀 쪽**이다.
단 제품마다 반대인 경우가 있으니 **사진으로 확인**하고, 애매하면 **암수 둘 다 들어있는 세트**를 산다.

> 💡 더 확실한 방법: **"JST 커넥터 연장 케이블"** 을 사면 한쪽은 암, 한쪽은 수가 달려 있다.
> 가운데를 잘라 쓰면 암수 고민이 사라진다.

### 14-4. 책상에서 배선 — 실제 배선도

#### ⚠️ 먼저 — "책상에서"의 정확한 의미

9장 2번에서 차를 **완전히 조립**하므로, 이 시점에 **모터는 이미 차 안에 들어가 있다.**
모터를 다시 빼내는 게 아니다.

| | |
| --- | --- |
| 차 | **조립된 상태 그대로.** 보드 `49` 에서 **모터 커넥터만 뽑아** 차 밖으로 빼낸다 |
| ESP32 · DRV8833 · 빵판 | 차 **밖** 책상에 |
| 🔴 차 자세 | **컵·책 위에 올려 바퀴를 공중에 띄운다.** 바닥에 놓으면 그대로 굴러간다 |

즉 "차체에 **넣지** 않는다"는 건 **ESP32 를 차 안에 집어넣지 않는다**는 뜻이다.
차량 탑재는 9장 12번에서 한다.

> ⚠️ **이 단계는 하네스가 있어야 시작된다.** 모터 커넥터(JST)를 빵판(2.54mm)에 직접 꽂을 수 없다.
> 순서: 조립 → 커넥터 실측(14-1) → 하네스 주문(14-3) → **하네스 도착** → 이 단계

이 단계의 ESP32 전원은 **PC USB** 다. 배터리를 따로 준비할 필요가 없다.

```
 [PC] ══USB══→ ESP32-C3
                  │
                  ├── GPIO 3  ──────→ AIN1  ┐
                  ├── GPIO 4  ──────→ AIN2  │
                  ├── GPIO 5  ──────→ BIN1  │  DRV8833
                  ├── GPIO 6  ──────→ BIN2  │
                  ├── GPIO 7  ──────→ SLP   │
                  └── GND ───────┬──→ GND   ┘
                                 │            │
                                 │            ├─ AOUT1/AOUT2 ──→ 구동 모터 (50)
                                 │            └─ BOUT1/BOUT2 ──→ 조향 모터 (48)
                                 │            │
 [AA 3개 4.5V] ──────────────────┴────────────→ VM
```

> 차체 탑재(9장 12번) 때는 `[PC] ══USB══` 자리에 **AA 팩 공용** 또는 **1S 리포** 가 들어간다.
> 어느 쪽을 쓸지는 5-3 의 단계적 판단표를 따른다. **배선 구조는 동일하다.**

#### 🔴 가장 흔한 실수 — GND 를 서로 연결하지 않는다

ESP32 전원(USB)과 모터 전원(AA)이 **서로 다른 소스**다.
이때 **두 GND 를 반드시 서로 연결**해야 한다 — 위 그림의 `┴` 지점이다.

안 하면 신호의 기준점이 없어서 **아무것도 동작하지 않는다.** 초보자가 가장 많이 틀리는 부분이고,
"배선은 다 맞는데 왜 안 되지" 의 90% 가 이거다.

> AA 팩을 ESP32 와 공용으로 쓰는 경우(5-3 의 1번)에는 전원이 하나이므로 이 문제가 없다.
> 대신 리셋 위험이 생긴다 — 트레이드오프다.

#### 콘덴서 3종 — 어디에 다나

| 콘덴서 | 위치 | 목적 |
| --- | --- | --- |
| 0.1µF ×1 | 모터 **단자 A ↔ 단자 B** 사이 | 브러시 아크 노이즈 |
| 0.1µF ×2 | **각 단자 → 모터 금속 몸통** | 같음 |
| 470µF ×1 | DRV8833 **`VM` ↔ `GND`** | 순간 전압 강하 완충 |

> ⚠️ **470µF 전해 콘덴서는 극성이 있다.** 긴 다리가 `+`(VM), 짧은 다리가 `GND`.
> **거꾸로 꽂으면 터진다.** 0.1µF 세라믹은 극성이 없어서 방향 무관하다.

#### 모터 제어 진리표 (DRV8833, sign-magnitude)

| `AIN1` | `AIN2` | 동작 |
| --- | --- | --- |
| PWM | LOW | 전진 |
| LOW | PWM | 후진 |
| LOW | LOW | 관성 정지 (coast) |
| HIGH | HIGH | 제동 (brake) |
| — | — | `SLP` = LOW 면 **전 채널 정지** |

> 방향이 반대로 돌면 **모터 선 2개를 서로 바꿔 꽂으면 된다.** 코드를 고칠 필요 없다.

#### 첫 테스트 순서

순서를 지켜야 뭐가 잘못됐는지 알 수 있다.

1. **모터를 붙이지 않고** USB 만 연결 → ESP32 가 부팅되나 (내장 LED `GPIO 8` 로 확인)
2. **구동 모터 1개만** 붙이고 PWM **30%** → 도나
3. 조향 모터 추가
4. **바퀴는 달지 않는다** — 달면 책상에서 굴러떨어진다

**바퀴를 손으로 잡고 오래 누르지 않는다.** 그 상태(스톨)가 전류 최대이고, 드라이버 발열의 원인이다.
